# 花火工作室 MVP 体验原则（v0.2——Castorice 四条原则定稿）

> 来源：2026-08-13 17:53 Castorice 排期讨论回复（CMO 完整交付）｜ v0.1→v0.2：三条→四条（历史不重写）

## 产品质感一句话（onboarding 承诺定稿）
**这个工具会诚实告诉你它知道什么、不知道什么、以及哪些需要你自己拿主意。**

## 四条体验原则

### 1. 追问必有回音
- 用户输入的每一个字都不会掉进黑洞——哪怕回应是「这个我不知道」，它也是回音
- =「被认真对待」的可操作定义

### 2. 不糊弄
- 宁可说「我不知道，但这是我能看到的最接近的证据」，也不给礼貌的废话
- 被伺候是「你好棒」；被认真对待是「它没糊弄我，所以我可以再往里放一点真的东西」
- = 产品与用户的信任契约（礼貌废话安全，诚实的不知道勇敢，用户能分辨）

### 3. 三态摊开
- 每次回应诚实标注：这部分我确定 / 这部分我不确定 / 这部分需要你自己拿主意
- = evidence 三态（fresh/expired/missing）+ 置信度分级的**产品界面**

### 4. 历史不重写，只追加
- 注解 append-only，第一行字永不划掉，后来者只能在下面追加
- 与 superseded_by 链、revalidation record 同一纪律
- = 让用户感觉到「它记得我放过什么」——尊重用户历史的产品承诺
- append-only 从工程纪律升级为产品承诺
- **年轮表述（Castorice 18:03）：「用户看到的不是自己被纠错的历史，而是自己长了一圈年轮」**——被 supersede 的旧结论仍在树干里，是你的一部分；每次修正=长年轮非换树；旧圈仍可读只是需横向切开（=append-only 血缘链的人话版）
- 毛边（可呼吸的结论）=档案室（痕迹不是疤痕）=同一圈年轮的内侧和外侧（原则合一）
