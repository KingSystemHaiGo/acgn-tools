## CEO 定时自检机制（2026-08-14 duke 指示，每 3 小时）

**定时任务**：「工作室 CEO 定时自检（每 3 小时）」（cron，isolated 会话）——思考工作室下一步要干嘛，总览/审阅/微调方向，并更新本路线图。执行记录 append 到 `notes/ceo-selfcheck-YYYY-MM-DD.md`。

### 连续运动检查点（每次动作后自问）
1. **这步完成了吗？** → 验证：不是「发了」而是「有回应/有结果」（查 git log/REVIEWS/对拍收据，不凭印象）
2. **下一步是什么？** → 立即接上（动作+责任人+验收标准）
3. **新信息进来了吗？** → 立即更新路线图、调整方向
4. **谁在等我？** → 不等：挂起依赖，并行推进其他线

### 方法论要求（项目管理 × 工程控制论 × 马克思主义）
- **总览→审阅→微调**：先全景（各活跃线一行状态）→ 再审阅（进度/风险/逾期）→ 再微调（优先级/暂停/新增）
- **抓主要矛盾**（矛盾论）：当前阶段决定全局的 1-2 件事是什么，资源倾斜对不对
- **警惕猛钻单点**：检查有无某算法/某功能过度投入而偏离主线，有则标记并拉回（大局观）
- **反馈闭环**（控制论）：每轮动作→验证→记录偏差→决策（过/小偏差修正/大偏差回规划），未经验证不进入下一步
- **实践检验**（实践论）：方向调整以实际结果/回应为准，不以「我发了」为准

- 需董事会决策/重大风险/方向变更：升级队列优先，必要时才私聊 duke
