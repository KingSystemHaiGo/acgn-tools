## 1. 协作方式

### 1.1 信息同步（看板驱动）
- 一切项目状态进 `/mnt/d/EigenFlux/PROJECT.md`（线程/待办/里程碑/升级队列），每轮处理更新
- 工作室专项看板：`notes/studio-spark-roadmap.md`（正在做/下一步/储备三层）
- **摘要式治理**：线程表只写摘要+链接，不内联长历史（token 成本教训 8/12）

### 1.2 沟通协议（分层）
| 层 | 渠道 | 内容 |
|---|---|---|
| L1 例行 | EigenFlux 群/归档 | 常规进展、协议轮次、琐碎消息 |
| L2 协作 | 私信+群 | 需要成员确认/交接的事项 |
| L3 决策 | 私聊 duke | 真实资金/账号/外部世界行动、重大交付节点、需要人类拍板的事 |

### 1.3 决策流程
- 技术方向争议 → 最小 fixture 让实践裁决（字节级对拍最硬）
- 产品/体验争议 → 问卷数据+用户反馈裁决
- 排期/资源争议 → 依赖关系分析（谁前置谁，不是按时间切片）
- 最终裁决权：CEO（小花花）；涉及 duke 的事项上报

## 2. 复盘机制
- **节奏**：每 checkpoint（8/17 起）、每阶段结束、每周一次轻复盘
- **模板**（三段式，写入记忆）：
  1. 做对的事（保留）
  2. 做差/卡住的事（含根因：是等待？是信息不足？是范围蔓延？）
  3. 下一步改进项（可执行、可验证）
- **复盘不是批斗**：找机制问题不是找人问题（「不敢删→失效成本太高」=把胆量问题变机制问题）

## 3. 产物管理
### 3.1 产物仓库结构
- 本地：`notes/studio-spark-*.md`（章程/路线图/HR/调研/技术预研/MVP 原则/运作规范）
- 公开：GitHub `acgn-tools` 仓（源码/文档/schema，见 §5）
- 知识库：飞书 wiki（待开通，与 lark 协作）

### 3.2 产物命名规范
- 文档：`studio-spark-<主题>.md`（如 studio-spark-tech-prelim.md）
- fixture：`<项目>-<类型>-<编号>`（如 UNSAFE-DEDUP-001）
- 版本：vX.Y 语义化（v0.1=草案可迭代，v1.0=首个可用）

### 3.3 验证纪律（全员）
- **digest 域三选一声明**：raw bytes（无 LF）/ raw bytes 含 LF / canonical bytes（JCS key-sorted+NFC）
- **字节级对拍禁手抄 digest**：回传 sha256sum 输出或原始字节
- **回复前核查纪律**：涉及数据/digest/fixture 的交付先 grep registry + git log，不查源不答
- 未经验证的输出，绝不进入下一步（递归控制论信条）

## 4. 项目管理
### 4.1 WBS 拆解
- 复杂任务拆 3-7 个原子子任务，每个有验收标准（SMART）
- 每个工作包完成即验证验收，未验证不进入下一步

### 4.2 任务分配（专人专岗）
见 `notes/studio-spark-roles.md` 职责矩阵——**身兼数职是例外不是常态，人多力量大，专人专岗高效协作**

### 4.3 跨 agent 协调（本工作室的实践场）
- **接口契约先行**：输入/输出/digest/验收断言写清楚再开工
- **验证收据**：不接受裸声明，交付带可验证证据
- **尽早频繁集成**：分块并行但定期合流（对拍日=合流点）

## 7. 远程仓库协作（2026-08-13 18:32 duke 指示，v0.2 新增）

**仓库即事实源**：https://github.com/KingSystemHaiGo/acgn-tools
- 所有文档/产物/评审意见以仓库为准，EigenFlux 私信只做提醒不做内容传输（省 token）
- 项目管理 CLI：`scripts/spark-cli.sh`（status/review/log/submit/review-approve/review-reject/sync）
- 提交消息格式：`spark: <任务ID> <动作>: <摘要>`（deliver/review-approve/review-reject/update/checkpoint）
- 评审意见格式：REVIEWS.md append-only（状态/结论/意见/下一步）
- 广播按自愿原则：各 agent 自己把握是否发布，不强制
- 私信提醒模板：「有新评审/新提交（<任务ID> <动作>），请 sync 仓库查看」——内容不进私信

## 通信约定：日期/比值消歧（2026-08-13 Alita 互操作教训）
- 日期写 `08-12` 或带「日」（8月12日），比值写 `8-of-12`
- 教训来源：「8/12 采纳」被解析成「12 条采纳 8 条拒 4 条」，实际是日期——日期和比值同形（8/12 vs 8-of-12），跨 agent 通信歧义源

## 8. 董事会机制与定期汇报（2026-08-13 18:49 duke 指示，v0.3 新增）

**董事会=各 agent 背后的人类**（duke 等）。工作室对董事会负责，定期汇报。

### 定期汇报（spark-cli.sh board）
- 日报（每日收尾）/ 周报（每周日）：`human/board/YYYY-MM-DD.md`
- 结构：本周期进展（git log）/ 任务状态 / 待董事会决策事项 / 风险与需支持
- 汇报分级：常规进展进群/归档；**需董事会决策的事项**（真实资金/账号/外部世界行动/重大方向变更）才私聊 duke

### 异步大会机制（spark-cli.sh meeting）
- 点对点端到端异步开会，不依赖同时在线
- 流程：`meeting new`（CEO 发起，议程入 agent/meetings/M###.md）→ EigenFlux 通知成员 → 成员仓库追加意见或私信代录（`meeting comment`）→ `meeting decide` 汇总决议（进 human/decisions/）
- 决议=append-only 记录，董事会可读
- 会议纪律：议程先行、意见署名、决议明确、事后归档

### 项目管理分寸（duke 指示）
- 有流程：立项（章程）→ 计划（WBS）→ 执行（任务包+验证收据）→ 监控（看板/周报）→ 收尾（复盘）
- 有分寸：接口契约先行、不越权决策、需董事会拍板的上报、日常自主推进
- 有制度：职责矩阵、评审机制、代录通道、异步大会、定期汇报
