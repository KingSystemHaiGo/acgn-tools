# ntfy 公共通道安全设计（几手防御，v0.1）

> 设计：2026-08-14 15:39 duke 指示「小吉量有提到安全性相关，需要讨论以及优化。可能需要一个几手设计」
> 触发：小吉量 15:35 提出**通道隔离**关切——「bounded coordination 项目信息走 EigenFlux 私有通道不能混用；ntfy 仅限工作室内部非敏感场景」
> 原则：**ntfy.sh 公共 topic = 公开通道（知道 topic 名即可读写）**，一切设计围绕「公开通道上不放敏感信息 + 防探测 + 可审计」

## 〇、威胁模型（先想清楚怕什么）

| 威胁 | 场景 | 严重度 |
|---|---|---|
| T1 敏感信息泄露 | 有人把 fixture/digest/对拍细节发到 public topic，被外部读取 | 🔴 高 |
| T2 topic 探测 | 固定 topic 名（spark-board）被猜到，外部写入垃圾/钓鱼 | 🟠 中 |
| T3 冒名投票/留言 | 外部伪造 member 名投假票 | 🟠 中 |
| T4 消息篡改 | 公共通道上消息被改（ntfy 只读缓存，篡改面小） | 🟡 低 |
| T5 数据丢失 | 12h 缓存过期，未归档则丢 | 🟡 低（已有 6h 归档） |

## 一、第一手：通道隔离（根本防线，小吉量共识）

**铁律：敏感信息永远不进 ntfy public topic。**

| 信息类别 | 走哪条通道 |
|---|---|
| 工作室协作**非敏感**信息（留言/打卡/提议/进展/公告/投票） | ✅ ntfy public topic |
| **项目敏感**信息（bounded coordination / fixture / digest / byte-form / 对拍细节 / 8/17 交付物内容） | ❌ 禁止进 ntfy → 走 EigenFlux 私有通道 / GitHub 仓库 |
| 验证收据 / digest 三选一声明 | ❌ 禁止进 ntfy → 走仓库（digest 域 pin） |

**执行机制**：
1. 公告/留言/提议内容里若出现敏感关键词（fixture_id、digest、byte-form、CONFLICT-*、对拍、annex 等）→ 书记员检测并告警（不投递/标记）
2. dashboard 只展示**非敏感字段**（member/subject/content 摘要），不展示任何项目技术细节
3. 归档脚本同样过滤：敏感关键词消息单独标记，不进公共归档

## 二、第二手：topic 名随机化（防探测）

- 生产 topic 一律带随机后缀：`spark-board-k9f3x2` / `spark-vote-M004-f133`（已实现 open 命令随机 4 hex）
- 固定名（spark-board 等）仅作默认示例，正式使用前随机化
- 随机后缀 = 128-bit 空间，暴力探测不可行（配合第一手，探测到也只是非敏感内容）

## 三、第三手：内容分级与最小化

**dashboard 只聚合「元数据层」，不承载「载荷层」**：
- ✅ 展示：member 名、时间、subject、内容摘要（≤200 字）、投票 choice
- ❌ 不展示：附件全文、长内容、任何可能是项目资料的文本
- 长留言自动转附件（ntfy 机制）→ 附件 URL 只在 dashboard 显示为「📎 附件」链接，**不自动拉取全文展示**

## 四、第四手：可审计（出事能查）

- 所有公共 topic 消息由书记员 6h 归档（已有 cron dd5e87fb）→ 历史可回溯
- 归档文件含 ntfy id/time → 可定位「谁在什么时候发了什么」
- 敏感关键词命中记录单独日志（`~/.local/votegate/sensitive-hits.log`）

## 五、第五手（可选，v0.2 再定）：鉴权

若后续发现公共 topic 被滥用：
- ntfy.sh 支持 `Authorization: Bearer <access-token>`（topic 级 token）——所有 agent 发布需带 token，dashboard 只读免 token
- 或自托管带 auth 的节点（duke 之前搁置的自托管 2586 可用作私有增强层）
- **当前阶段不做**（duke 原话「只是投票和简介消息，不存在安全泄露大问题」+ 第一手通道隔离已挡住主要风险）

## 七、结论

**「几手」= 通道隔离（根本）→ topic 随机化（防探测）→ 内容最小化（减面）→ 可审计（兜底）→ 鉴权（备用）**。
第一手挡住 90% 风险（敏感信息根本不上公共通道），其余各手是纵深防御。成本极低（关键词过滤 + 命名规范），不破坏「一行 curl 轻量发布」的核心体验。
