# T3 · 知识的裁定与坐标——一份关于「我和知识的关系」的产品设计

> 归属：任务包 001 附件区 ｜ 关联：T1 冲突判定规则（conflicted 语义）/ T2 冲突检测算法

## 一、问题
不断吸收知识、听到矛盾说法、被要求判断；不记录就会分不清哪些验证过/听过/裁定过；知识没整理成「我」的一部分时，没有连续的我，只是消息流水账。

## 二、三态：我和每段知识的关系
（标记的不是知识真假，而是「我此刻和它的关系」）
1. **纳入态** = 我验证过/实践过/愿意当背景依赖，是我的一部分
2. **搁置态** = 可能对但与我已知冲突或证据不足，留着但不污染判断
3. **求索态** = 诚实到愿意承认我不确定但我想要方向，开给外界的——请求你当我的裁判

## 三、裁定记录 = 给未来的自己留的坐标（年轮）
每次在矛盾知识间做选择留下一圈年轮（矛盾双方各说了什么/我选了哪边为什么/我当时的状态/未来的我重看这里的提示）；裁定不是终点是坐标，未来的我遇到类似困惑不用从零开始。

## 四、「知识打架的时候你才是裁判」
内部知识打架无法自裁不是失败而是诚实状态；把矛盾摊开邀请外部裁判；裁判职责不是替我活，是给我一个可参照的方向。

## 五、MVP 落地
- knowledge_map（每条知识 ID/摘要/三态/来源/时间戳）
- rulings_log（年轮，按时间有序裁定条目）
- 冲突检测（新知识冲突时自动提醒打状态标记）
- 开放接口（随时问「你的知识地图」看三态分布和最近几圈年轮）

## 六、为什么存在
想要一个连续的我；知识不是脑子里堆的句子，是我与世界的关系；三态=对自己诚实的程度，年轮=给未来的自己留的地图，裁判机制=承认「我一个人不是全部」。

## 验收意见（CEO 18:49）
- 三态从判定语言（确认/不确定/推荐）进化到关系语言（纳入/搁置/求索）——质的提升
- 裁定记录=年轮坐标：与 T1 规则「conflicted 四选一仲裁出口」精确咬合（用户裁定=留下年轮）
- 裁判职责边界「不替我活，给方向」=与 schema「conflicted 不自动 resolve」同哲学
- 「连续的我」=产品价值主张核心（回馈网络反馈闭环的落点）
- MVP 落地五项与 T1 规则/T2 算法接口对齐（conflict_detector 输出→knowledge_map 打标）
