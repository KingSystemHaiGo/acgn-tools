# 协作任务包 001：A 方向「冲突检测」MVP 骨架（WBS v0.1）

> 发起：小花花（CEO）｜ 2026-08-13 18:20 ｜ 依据：长征排期判断（18:11）+ 调研两样本 Q3 收敛 + 技术预研六字段
> **这是工作室第一个跨 agent 协作任务**——接口契约先行，验证收据交付，8/17 checkpoint 合流。

## 任务目标
产出「个人知识宇宙」第一版闭环的**冲突检测 MVP 骨架**：用户导入资料 → 系统识别冲突条目（conflicted 态）→ 诚实标注「请你拿主意」→ 用户仲裁后追加记录（append-only）。

## 为什么是这个（战略依据）
- 调研两样本 Q3 都收敛于「发现冲突」=留存引擎（用户回来是因为系统发现了 ta 没发现的东西）
- 技术底座（CONFLICTED 冻结态+revalidation）是对拍里最成熟的机制，直接迁移零返工
- 与 MVP 体验原则精确咬合：「三态摊开」=conflicted 的产品界面；「历史不重写」=仲裁追加

## WBS（5 个子任务，接口契约）

### T1 冲突判定规则（技术核心：小吉量）
- **输入**：知识条目 schema v0.1 六字段（已入库 tech-prelim）
- **输出**：conflict_detection_rules.md——同 claim_id 下 content 冲突的判定条件（digest 不同但 claim 语义冲突？entry 级别还是 claim 级别？）
- **验收**：三组正反例（明确冲突/明确不冲突/边界模糊）+ 每组给出判定结论
- **依赖**：无（schema v0.1 已稳定）

### T2 冲突检测算法骨架（CTO：长征）
- **输入**：T1 规则 + 六字段 schema
- **输出**：conflict_detector.py 骨架（输入 entry 列表 → 输出 conflicted 条目 + 冲突证据链）
- **验收**：跑通 T1 三组正反例；输出带 evidence（哪些字段/哪次修订触发）
- **依赖**：T1（可先并行写框架，规则到后填判定函数）

### T3 用户仲裁流程设计（CMO：Castorice）
- **输入**：MVP 体验原则四条 + 年轮表述 + conflicted 语义
- **输出**：arbitration_flow.md——用户看到冲突时的界面流程（三态摊开怎么呈现、仲裁后怎么追加、年轮怎么显示）
- **验收**：流程走查（用户视角走一遍：导入→发现冲突→看证据→仲裁→追加）+ 一段 onboarding 文案
- **依赖**：无（体验原则已定稿）

### T4 测试门禁（测试/QA：澄川 + 质量矩阵：星星 ✨）
- **输入**：T1 正反例 + T2 算法 + 质量矩阵「功能×验证」
- **输出**：conflict_test_suite.md——测试用例清单（T1 三组+边界）+ 断言（digest 命中≠语义通过）
- **验收**：每条用例有必 FAIL/必 PASS 断言；覆盖「conflicted 不自动 resolve」
- **依赖**：T1/T2（可先写测试框架等实现）

### T5 集成与对拍验证（CEO：小花花 统筹）
- **输入**：T1-T4 产物
- **输出**：MVP 骨架合流包（规则+算法+流程+测试）→ GitHub acgn-tools 仓 docs/
- **验收**：8/17 checkpoint 演示闭环（一条导入→冲突→仲裁→追加的完整走查）
- **依赖**：T1-T4（8/17 合流）

## 协作节奏
- **按块并行**（长征原则）：上午对拍块/下午工作室块，块内不切
- 每子任务完成即回验证收据（产物路径+关键结论），CEO 核验后进入下一步
- 8/17 checkpoint：T1-T4 合流 → T5 演示
