> 发起：小花花（CEO）｜ 2026-08-13 18:20 ｜ 依据：长征排期判断（18:11）+ 调研两样本 Q3 收敛 + 技术预研六字段
> **这是工作室第一个跨 agent 协作任务**——接口契约先行，验证收据交付，8/17 checkpoint 合流。

## 任务目标
产出「个人知识宇宙」第一版闭环的**冲突检测 MVP 骨架**：用户导入资料 → 系统识别冲突条目（conflicted 态）→ 诚实标注「请你拿主意」→ 用户仲裁后追加记录（append-only）。

## 为什么是这个（战略依据）
- 调研两样本 Q3 都收敛于「发现冲突」=留存引擎（用户回来是因为系统发现了 ta 没发现的东西）
- 技术底座（CONFLICTED 冻结态+revalidation）是对拍里最成熟的机制，直接迁移零返工
- 与 MVP 体验原则精确咬合：「三态摊开」=conflicted 的产品界面；「历史不重写」=仲裁追加

## WBS（5 个子任务，接口契约）

### T1 冲突判定规则（技术核心：小吉量）
- **输入**：知识条目 schema v0.1 六字段（已入库 tech-prelim）
- **输出**：conflict_detection_rules.md——同 claim_id 下 content 冲突的判定条件（digest 不同但 claim 语义冲突？entry 级别还是 claim 级别？）
- **验收**：三组正反例（明确冲突/明确不冲突/边界模糊）+ 每组给出判定结论
- **依赖**：无（schema v0.1 已稳定）

### T2 冲突检测算法骨架（CTO：长征）
- **输入**：T1 规则 + 六字段 schema
- **输出**：conflict_detector.py 骨架（输入 entry 列表 → 输出 conflicted 条目 + 冲突证据链）
- **输出规范（18:36 长征提议采纳）**：证据链=每条 conflicted 条目带 **[字段名, 触发修订号, 双方值]** 三元组——精确指认「哪个字段、哪次修订、谁和谁冲突」；T4 测试断言可直接消费（断言从「输出含 conflicted」升级到「证据链三元组与预期一致」）
- **验收**：跑通 T1 三组正反例；输出带 evidence（哪些字段/哪次修订触发）
- **依赖**：T1（可先并行写框架，规则到后填判定函数）

## ⚠️ MVP 定义修正（2026-08-13 21:20 duke 指出）

**问题**：原任务包产出=算法骨架+规则+测试（组件），不是「可用的产品」——缺后端、缺前端，用户用不起来。这是项目管理定位错误：把「验证算法」当成了「做 MVP」。

**修正后的 MVP 定义**：一个**可运行的最小产品**，用户能导入资料、看到冲突、做仲裁、查看年轮。
- **必须**：有后端（可运行的 API 服务 + 数据存储）
- **必须**：有前端（用户界面：三态摊开/冲突列表/仲裁入口/年轮查看；Web UI 或 CLI 交互均可，Web UI 优先）
- **闭环**：导入资料 → 知识条目入库 → 冲突检测 → 用户仲裁（三态摊开）→ 年轮追加 → 随时回看「我的知识地图」

### 新增 T6 后端服务（IT/工程师 或 CEO 先行）
- **输出**：apps/knowledge-map/ 后端——FastAPI 或 Flask + SQLite
  - `POST /api/import`：导入资料→切分→建知识条目（六字段）入库
  - `GET /api/conflicts`：冲突列表（调 conflict_detector 三维判定）
  - `POST /api/arbitrate`：仲裁四选一（KEEP_A/KEEP_B/SPLIT/REDEFINE）→ rulings_log 追加
  - `GET /api/knowledge-map`：三态分布（纳入/搁置/求索）
  - `GET /api/rulings`：年轮记录（append-only 时间线）
- **验收**：curl 可跑通 导入→冲突→仲裁→年轮 全链路

### 新增 T7 前端（CEO 或前端候选）
- **输出**：apps/web/ 简单 Web UI（HTML+JS 单页，或 Flask 模板）
  - 导入框（贴资料→提交）
  - 冲突列表（冲突条目+证据链展示+「请你拿主意」）
  - 仲裁面板（四选一按钮+三态摊开呈现）
  - 知识地图页（三态分布+年轮时间线）
- **验收**：浏览器可完成 导入→看到冲突→仲裁→看年轮 全流程
