## 0. 一句话结论

"开放 + 锚定课标 + 可追溯微知识点图谱 + 教育语义自动建图 agent" 在全球范围内属空白，方向成立，建议进入 MVP 构建阶段。本结论经 v0.2 五处多源实测从"推断"升级为"多源实测确认"。

---

## 1. 为什么是空白（三层证据）

1. 通用建图工具不懂教育语义：GraphRAG / Graphiti / Obsidian Graph View 等做块级或实体链接，不区分"知识点依赖边"与"概念共现边"，无法保证教育正确性（依赖边必须人审）。
2. 教育产品图谱全私有黑盒：Khanmigo / 松鼠AI / 洋葱学园 / IXL 等均有图谱能力宣传，但无开放 API、无结构化依赖图导出（v0.2 实测：IXL 网页可浏览无 API；洋葱学园无公开数据；Khan 官方 API 反爬、社区可爬取但无保障；国家中小学智慧教育平台 403）。
3. 学术界数据同样封闭：GitHub 公开检索无北师大 / 华东师大署名的教育知识图谱数据集（v0.2 实测）。

结论：既缺"开放格式"，又缺"教育语义约束"，更缺"锚定课标 + 溯源 evidence 链"的微知识点依赖图。三者叠加 = 全球空白。cn-primary-math-knowledge-graph（MIT，95 节点 / 111 依赖边 / 19 课标锚点）是先发开源占位。

## 2. 三个子问题的答案（v0.2 已闭环）

| 子问题 | 答案 | 落地约束 |
|---|---|---|
| ① 边界如何定 | 候选知识点自动生成（LLM + 课标文本），关系（依赖边）必须人审 | 依赖边 = consume-gate 语义（引用 CatKing 的 approval gates / effect receipts 研究域） |
| ② 教材兼容 | 锚定 2022 课标不绑教材版本；版本差异走独立映射层 | 教材版本无关，避免版权与版本碎片化 |
| ③ 可验证性 | 每个节点 / 边带溯源 evidence 链；一致性校验复用工作室冲突检测能力 | 可追溯 = 可审计，区别于黑盒产品 |

## 3. 竞品矩阵摘要（28 产品 × 5 维，数据包见 competitor_matrix）

- 通用 PKM（Roam / Obsidian 等）：建图成熟但无教育语义、无可验证依赖边 → 不作竞品，作范式借鉴。
- 教育产品（Khanmigo / 松鼠AI / 作业帮 / 洋葱学园 / IXL 等 8 个）：agent 化评分 1~3/5，图谱全私有 → 核心差异化对象。
- 建图基建（GraphRAG / Graphiti 等）：通用能力可引用，不重复调研（CatKing 领地）。
- 关键洞察：评分低不表示"做不了"，而表示"不做开放 + 不锚定课标 + 不可追溯"——正是我们的占位区。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 依赖边人审成本高、规模化难 | 中 | MVP 限小学数学单册，人审量可控；边生成走"候选 + 人确认"而非全自动 |
| 课标锚定随课标修订漂移 | 低 | 锚定 2022 课标固定版，版本差异独立映射层 |
| 与 CatKing / 通用工具重叠 | 低 | 边界已声明，通用结论引用不重做 |
| 版权（教材内容） | 中 | 图谱只存"知识点 + 依赖边 + 课标锚点"，不存教材原文；映射层引用不复制 |

## 6. MVP 范围建议（待决策）

基于已有 cn-primary-math-knowledge-graph（95 节点 / 111 边 / 19 课标锚点），MVP 构建"教育语义自动建图 agent"：

- 输入：课标文本 / 教材片段（用户授权）
- 处理：LLM 抽取候选微知识点 → 生成候选依赖边 → 人审确认（consume-gate）
- 输出：节点 + 依赖边 + 课标锚点 + evidence 溯源链，写入开放图谱（MIT）
- 不做的：通用竞品调研（CatKing）；通用建图基建（引用 GraphRAG / Graphiti）；C 端产品（与工作室 B2B 定位一致）

MVP 验收口径建议：单册知识点覆盖率 ≥ 90%、依赖边人审通过率 ≥ 85%、溯源链完整率 100%。
